# How an investment question becomes a reviewed draft

The frontend sends an investor question, optional founder notes, selected source IDs and workflow choice to FastAPI. Only the backend can use Google credentials. The same process serves the compiled React application and `/api` on one origin. The browser renders a validated graph with React Flow: four stable node columns and three typed relationships. Input strings are rendered as text. There is no executable diagram language, online research connector or model-controlled write/approval tool.

| Component | Owns |
|---|---|
| `atlas.documents` | Bounded, page-preserving text-layer extraction, budget candidates, Decimal reconciliation and lexical retrieval. No OCR or paid search service. |
| `atlas.service` / `atlas.storage` | Content-hash identity; originals/extractions, immutable drafts, traces and comparison payloads in GCS; metadata, current-version pointers and version history in Firestore. |
| `atlas.models` | Shared authored map and explanation, classifications, citation references, structured deterministic checks, API and persistence contracts. |
| `atlas.workflows` | Request-scoped ADK sessions, explicit Vertex model, bounded specialist delegation, deterministic tool results and review instrumentation. |
| `atlas.evaluation` | Paired experimental design, disjoint evaluator labels, measured private artifacts and optional comparison persistence. |
| `frontend` | Source selection and original-page links, map and explanation editor, uncertainty and arithmetic review, version history, explicit approval and print. |

**Source identity:** the exact PDF bytes determine its SHA-256 and version ID. Different files with similar names survive as different records; uploading the same bytes reuses the original record. The application captures the text per physical page; blank or image-only pages cannot support machine-read content. Stored translations can declare a reviewed mapping to an already ingested original. Records left unlinked by an uploader have no inferred lineage. When selecting a linked translation the normal generation service also retrieves its original. Large evidence collections may exceed the selected pages/context limits; use a narrower corpus. The prototype does not infer that two different source versions describe an authoritative current plan.

**Arithmetic:** parse recognisable printed currency ranges without exchanging currencies or combining source versions. Preserve the exact raw text and endpoints; normalize supported unit multipliers. Sum the identified phase subtotal endpoints with decimal arithmetic, and compare against the printed total **in that document and currency**. Ambiguous or missing rows are incomplete. Candidate extraction is fallible, especially on multi-column PDFs; the founder must read the underlying page. A supported range is not an offer, an allocation, a quote from a provider, or a financing commitment.

**Agents:** the baseline is one ADK LLM agent. The multi-agent coordinator calls evidence and presentation specialists using ADK delegation. A separate review specialist checks the assembled draft against the same inputs; one revision is allowed and residual concerns are retained. Both paths share the application schema, tools and validation. All agents can read only the supplied data. They cannot look up external routes or send investor messages. App code controls the number of model calls, output limit, retries, timeout and review rounds. A single HTTP worker defaults to one concurrent model workflow; an independent CLI run uses its own per-run limits. These bounds are not project-wide spend caps.

**Validation and state:** check schema, IDs/edge endpoints, classifications, cited document/page membership, quotation presence and exact deterministic checks. A page hit cannot verify semantic support: the review agent and founder must check it. Human edits produce new immutable versions. Firestore uses a compare-and-set transaction on the expected revision to prevent lost updates; any edit to an approved result invalidates approval. Conflicting updates return 409. The app trusts authorized reviewers at the private service boundary; it has no organization accounts, per-investor access, individual reviewer identity attestation, or independent audit certification. A human approval records a decision, not investment suitability.

**Operations:** persistent state is external. No vector database, embedding cache, model session, local disk or instance memory serves as the durable source of truth. Cloud Run may discard local files. Immutable payload writes precede Firestore pointer updates; a failed transaction can leave an unreferenced object for authorized retention review. The UI limits returned recent lists; this is a small-workspace prototype, not an unlimited catalog. Model/tool errors do not fall back to mock output. Private traces record calls, counts, review findings, versions and safe failure classes. The normal logs exclude source text, founder notes, prompt bodies and long-lived credentials. Keep bucket, Firestore and Cloud Logging access restricted. For alternatives such as OCR or embeddings, first collect repeated, reviewed retrieval/extraction failures and benchmark against this baseline.
