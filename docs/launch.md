# Founder handoff checklist

Use this checklist to record **observations**, request IDs, selected corpus hashes, reviewer and dates in `private/`. A checked configuration banner is not a credential, IAM or model test.

1. **Local setup:** install Node 22.21.1 with npm, uv, and Python 3.11. Run `bash scripts/dev.sh` from the checkout. Open `http://127.0.0.1:8000`. Without cloud settings, view the empty workspace, source library, saved drafts and comparison. No placeholder answers are generated.
2. **Authorized account:** follow [Private Google Cloud handoff](cloud.md) for `.env`, ADC, APIs, an existing private bucket, Firestore Native database, runtime permissions and a currently supported Vertex model in the chosen region. Establish a budget and decide which documents may be transmitted. Do not send keys in chat.
3. **Live model smoke:** from repository root, run `uv run --project backend python -m atlas.smoke --live-model` once. This is a bounded, small, synthetic model connection check. It sends no company text. A success only establishes a response through the configured Vertex connection.
4. **Storage:** open Sources, upload an approved original and inspect page text, hash, language, page count, image warnings and budget fields. Upload the same bytes again and verify one source record with the same ID. Refresh or restart and reopen it. For a translation, select the original and supply the reviewed page mapping. Never infer the original from the filename. The private source review on the original workstation includes candidate mappings for founder confirmation.
5. **Full single-agent path:** ask one reported investor question and add optional founder notes. Select only the relevant sources. Generate one draft; inspect map connections, classifications, citations, calculation rows and explanation. Read the cited original pages. Treat budget numbers as source estimates; keep any conflict visible.
6. **Human review:** edit a node label and explanation, save, approve using the explicit founder action, reload and check the version history. Edit the approved result and save again: the new version must be a draft, with the prior approved version preserved. Print only the reviewed version. Anonymous company claims, funding allocations and promised returns do not belong in an approved card.
7. **Multi-agent and comparison:** run one corresponding multi-agent draft, inspect its evidence references and review warnings. Run **one** controlled pair using [Comparison](comparison.md) with `--persist`; confirm two measured arms, equal packet digest, per-call usage or explicit unknown values, failures, sample size and actual timing. Do not widen evaluation until the small run is reviewed.
8. **Controlled failure:** use a malformed, nonsensitive PDF or attempt a stale edit. Verify explicit failure and preserved prior version. No additional paid run is needed to establish these properties. A provider error must surface without producing a successful draft.
9. **Private deployment, separately authorized:** build the Linux image, deploy with the runtime identity, grant only named invokers and use the reviewer's authenticated Cloud Run proxy. Verify direct anonymous denial, authenticated browser access, persistence across a restart and the complete workflow. Record cost/usage and clean up resources under the owner's retention rules. This step has not been executed by the implementation.
